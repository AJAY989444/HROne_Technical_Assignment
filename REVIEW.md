# REVIEW.md

Defects found in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Returns `{"status": "ok"}` unconditionally without checking DB connection health. | If MongoDB is down or misconfigured, `/health` still returns 200 OK instead of HTTP 503. | Added `db.command("ping")` check inside try/except block, returning HTTP 503 on failure. |
| 2 | Global `MongoClient` initialization | `MongoClient` initialized without `tz_aware=True`. | PyMongo returns naive `datetime` objects, causing timezone mixing bugs, invalid subtractions, and leaking local server time. | Initialized `MongoClient` with `tz_aware=True`. |
| 3 | `compute_late_minutes` | (a) Uses `punch_in` tz replacement without IST awareness. (b) `minutes > 10` returns 0 for 10 min 1 sec late (09:40:01). (c) Ignores overnight shifts. (d) No second truncation. | Punching in at 09:40:01 IST produces 0 late minutes instead of 10. | Re-wrote helper with IST conversion, second truncation, strict > 10 min threshold logic, and overnight shift calculation. |
| 4 | `compute_work_hours` | Uses Python's built-in `round()`, which rounds half-to-even instead of half-up, and lacks input second truncation. | Work hours calculation for boundary values like 4.495 rounds down incorrectly to 4.49 instead of 4.50. | Used `decimal.Decimal` with `ROUND_HALF_UP` and truncated timestamps to whole seconds. |
| 5 | `compute_overtime` | Uses record `date` string for shift end without handling overnight shifts (where shift end is next day); lacks 30-min minimum threshold; mixes naive/aware datetimes. | An overnight shift ending at 06:40 IST computes negative overtime against previous day's 06:00. | Rewrote helper with overnight shift end adjustment and strictly enforced max(0, overtime) when overtime >= 30 min, else 0. |
| 6 | `create_employee` | Check-then-insert race condition; missing validation for `emp_code`, `email`, shift format, `joined_on` calendar date, and `shift_start != shift_end`; `created_at` uses naive datetime and leaks as ISO string instead of epoch ms. | Concurrent requests with same `emp_code` both pass check; invalid emails or negative/equal shifts are accepted. | Added Pydantic model validations, unique DB index on `emp_code`, duplicate key handling (409), UTC datetimes, and epoch ms boundary serialization. |
| 7 | `list_employees` | `skip = page * page_size` skips `page` pages (page 1 skips first `page_size` items); total count ignores `department` filter; results lack deterministic sort; `page` and `page_size` not validated. | `GET /employees?page=1&page_size=20` returns items 21-40; total count is wrong when `department` query param is provided. | Fixed `skip = (page - 1) * page_size`, updated `count_documents(q)`, added `.sort("emp_code", 1)`, and added query validation for `page >= 1` and `1 <= page_size <= 100`. |
| 8 | `punch_in` | Raises `TypeError` 500 when `emp_code` does not exist; uses server local timezone for `date`; check-then-insert race condition; `status` not validated (accepts `ABSENT`); `punched_at` falsy check fails on `0`; leaks `id` field; returns datetimes instead of epoch ms. | Punching in an unknown `emp_code` causes 500 Internal Server Error; concurrent punch-ins create duplicate records. | Handled 404 for unknown employee, unique index `{emp_code: 1, date: 1}` catching `DuplicateKeyError` (409), strict status validation (`PRESENT`, `WFH`, `ON_DUTY`), IST date calculation (R1), and serialization to epoch ms without `_id`/`id`. |
| 9 | `list_attendance` | Fetches entire collection into memory (`list(...)`) and sorts in Python; sort lacks `emp_code` tiebreaker; leaks `_id` as `id`; returns raw datetimes; missing legacy fields (`history`, `half_day`) not defaulted; no validation for `date_from > date_to`. | Memory crash / high latency on large datasets (100k docs); `date_from > date_to` returns 200 with empty list instead of 422. | Built DB-side pipeline/query with `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`, handled default fields (`history: []`, `half_day: False`), 422 on `date_from > date_to`, and epoch ms conversions. |
| 10 | Startup Indexes | No database indexes created at application startup. | Database scans full collection (COLLSCAN) for every query, causing timeouts on ~100k hidden dataset. | Added idempotent startup index creation for `employees` and `attendance_logs` collections. |

## Examined and Decided NOT a Defect:

1. **`load_dotenv()` default behavior**: `load_dotenv()` by default does not overwrite existing environment variables. Real environment variables supplied by the environment/grader correctly take precedence over values in `.env`.
2. **Synchronous (`def`) endpoints in FastAPI**: Standard `def` endpoint functions in FastAPI run in FastAPI's external threadpool worker threads, which prevents blocking the asyncio event loop during PyMongo synchronous I/O operations.
